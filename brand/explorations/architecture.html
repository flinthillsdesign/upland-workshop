Key Patterns
Read-heavy integration — Apps mostly read from each other. Nobody writes to another app's database directly.
ODIN owns users — Only app with UI for creating users and granting per-app access. All others read the auth DB.
Dual databases — Each satellite connects to the shared auth DB (read-only) + its own app DB (full CRUD).
Service-to-service auth — JWT or INTERNAL_SERVICE_TOKEN. Website order JSON is unauthenticated.
Client share links — Scheduler, Claire, Quotes, Agreements expose /share/:token for unauthenticated client views.
Convention over shared code — No shared component library. Apps copy the same patterns independently.
